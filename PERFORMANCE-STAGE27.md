# Stage 27 — experimental admission and diagnostic overhead
Based on Stage 26 and the supplied improvement brief. New switches default off; set in the environment before launching, one at a time.
- VICTORY_STRICT_ADMISSION=1: recheck texture admission before each queued mirror while room remains; recompute sparse admission per upload rather than sharing the first texture's limit; skip queue selection after adaptive time is exhausted. DXGI queries may themselves cost CPU time. This is not a hard VRAM cap or a reservation system. Existing resident texture refresh remains allowed.
- VICTORY_AGGREGATE_COPY_STATS=1: preserve aggregate compared/published byte totals without per-address hash maps or range timing detail. Only useful in diagnostics builds. Does not eliminate actual memory copies. Existing synchronization unchanged.
Validation: source substitutions checked; archive integrity checked. Cargo unavailable, so profile checker and Windows target compilation not completed. No GPU or gameplay tests. Compare same warmed scene with switches off/on separately; monitor frame time, texture backlog, shared VRAM, RAM, and visual correctness. Rollback: unset both switches. GPU detiling and memory synchronization redesign remain outstanding.
